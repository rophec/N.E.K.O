# 雀魂内部面板渲染稳定性 TODO

## P1：减少自动刷新造成的闪烁

状态：`TODO`

目标：保持后端识别和策略刷新速度不变，避免内部诊断面板因频繁整区重绘而闪烁、跳动或短暂空白，并降低无效的浏览器布局与绘制开销。

### 已确认原因

- 页面目前约每 700ms 拉取一次状态。
- 自动轮询期间，状态文字会反复在“刷新中”和就绪状态之间切换。
- 即使数据没有变化，手牌、牌河、副露、候选方案、识别流水线、计时日志等区域仍会清空并重建 DOM。
- 证据图更新过程中可能出现旧图提前消失、新图尚未加载完成的空白阶段。

### 待实施

- [ ] 自动轮询改为静默刷新；仅手动刷新、持续超时或错误时显示明显状态。
- [ ] 为局面快照和各显示模块建立 revision 或数据签名，只渲染发生变化的区域。
- [ ] 手牌、牌河、副露、风险候选和流水线数据未变时复用现有 DOM，不执行无条件 `replaceChildren()`。
- [ ] 证据图仅在图片 revision 变化时请求；新图预加载并解码成功后再原子替换旧图。
- [ ] 计时日志等重型诊断区域改为增量追加，或使用独立的较低刷新频率。
- [ ] 将同一轮产生的 DOM 写入合并到一次 `requestAnimationFrame` 中，减少布局抖动。
- [ ] 增加前端测试，覆盖“数据未变化不重建”“图片加载失败保留旧图”和“快速连续 revision 只显示最新版”。

### 验收标准

- 后端捕获、识别和策略计算频率不降低。
- 静止牌局下，内部面板不再周期性闪烁或切换“刷新中”。
- 单个区域变化时，其他区域不重建、不跳动。
- 证据图更新时旧图持续可见，直到新图完整加载。
- 连续快速更新时只呈现最新有效快照，不短暂回退到旧帧。
- 浏览器 Performance 记录中，无变化轮询的 DOM mutation、layout 和 paint 次数显著下降。

### 主要代码位置

- `static/main.js`：自动轮询、`refreshStatus()`、`renderDashboard()`、各区域 renderer 和证据图刷新。
- `static/style.css`：如需要，只增加稳定占位尺寸和图片切换效果，不用动画掩盖数据重建问题。
