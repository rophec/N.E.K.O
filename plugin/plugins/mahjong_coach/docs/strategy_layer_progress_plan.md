## 2. 当前结论

### 2.1 插件目前能做什么

- `[x]` 从截图识别自家手牌、自家副露、四家牌河和操作按钮。
- `[x]` 生成开局路线、保留牌、优先打牌和吃碰杠建议。
- `[x]` 根据向听数、有效牌、宝牌和已见牌进行本地牌效排序。
- `[x]` 发现立直玩家后进入防守分析，给出筋牌、现物、壁等风险依据。
- `[x]` 在插件页面显示识别流程、当前策略、牌面数据和逐步耗时。
- `[x]` 实时牌河会复核同一位置的牌；同一改判连续出现两帧后自动纠正旧记录。
- `[x]` 能识别具备明确斜边结算面板与和牌牌列的和牌结算画面。
- `[x]` 结算连续两帧确认后冻结上一局，直到新手牌连续稳定两帧才进入下一局。
- `[x]` 菜单遮挡、房间页、整场排名和误绑其他游戏时不会立即清空上一局。

### 2.2 插件目前不能可靠做什么

- `[x]` 已有专门的和牌结算画面检测器和结构化结算事件。
- `[ ]` **尚无足够真实样本可靠区分荒牌流局和途中流局。**
- `[x]` 已把“结算连续两帧出现”作为确定的小局结束事件。
- `[ ]` 没有自动读取四家点数、排名、场棒、立直棒并用于策略。
- `[ ]` 没有完整番种、符数、点数和合法和牌计算引擎。
- `[ ]` 没有接入可运行的 LLM 策略顾问；当前建议来自本地启发式算法。

当前代码同时拥有**明确结算边界**和旧版**间接换局确认**。相关代码依据：

## 3. 当前运行链

```text
截图
  -> 结算边界检测
  -> 牌桌定位/校准
  -> 手牌、副露、牌河、按钮识别
  -> 多帧状态合并
  -> 开局/检查点/操作窗口/防守判断
  -> 本地策略与打牌排序
  -> 浮窗和插件详情页
```

明确结算的小局边界是：

```text
playing
  -> settlement_candidate（第 1 帧）
  -> settlement_latched（第 2 帧）
  -> 冻结上一局手牌/副露/牌河/策略
  -> awaiting_next_round
  -> 12 至 14 张无副露新手牌连续稳定两帧
  -> playing
```

如果没有拍到结算画面，仍保留旧版间接兜底：

```text
旧牌河已有内容
  -> 当前牌河归零
  -> 新手牌连续稳定
  -> 间接确认新局
```

## 5. 部分完成功能

### 5.1 小局切换

- `[x]` 已有明确结算边界、间接新局兜底和两帧稳定条件。
- `[x]` 已有菜单遮挡保护，不会因一次手牌消失立即清空。
- `[x]` 已检测和牌结算画面并输出视觉证据、置信度和耗时。
- `[x]` 结算出现时冻结上一局状态，结算消失后等待新手牌。
- `[-]` 已区分和牌结算与普通画面；荒牌流局、途中流局仍缺真实样本，暂返回 `unknown` 而不硬猜。

### 5.2 牌河跟踪

- `[x]` 状态层按玩家增量合并弃牌，不会每帧直接清空。
- `[x]` YOLO 牌河检测结果在标准化牌桌上估算当帧中心，再按四个方向扇区归属；更外围的对手副露等牌不会写入 `discard_piles`。
- `[x]` YOLO 模式对原图和透视牌桌分别推理；牌河结果用玩家归属和框 IoU 对齐历史位置，而不是仅凭 `玩家 + turn_index` 跳过旧记录。
- `[x]` 同位置不同牌名需连续两次全量识别一致后才替换，并记录 `corrected_from`、纠错事件、待确认数和全量复核日志。
- `[x]` 普通新弃牌需连续两帧出现后才追加；吃碰杠窗口为保证实时建议，可以立即追加本次唯一弃牌。
- `[x]` legacy 模式保留下一槽增量检测，同时每 `8` 帧做一次全量复核。
- `[ ]` 尚未稳定实现“只检测刚打出的下一张牌”的独立事件检测。
- `[ ]` 尚未把每次弃牌绑定到明确的玩家动作时序。

当前纠错边界：历史弃牌即使之后因吃碰杠离开牌河，仍应作为“曾经打过的牌”保留，因此系统不会仅因某帧未检测到它就删除历史；本轮纠正的是错误区域写入、同位置错误牌名和单帧新增抖动。待玩家动作时序接通后，再安全区分“被鸣走”与“误检后消失”。
