# 雀魂插件全模块文案规范

更新时间：2026-08-11  
适用范围：四麻、外部原生悬浮窗、插件内部后台、策略结果、吐槽伙伴、识别与诊断状态。

本文是用户可见文案的统一基线。实现时应优先复用这里的名称和句式，避免同一功能在不同页面使用不同叫法。

## 1. 总体表达原则

### 1.1 信息顺序

所有结果先回答用户最关心的三件事：

1. 现在发生了什么。
2. 当前建议或观察是什么。
3. 为什么得出这个结论。

识别置信度、内部字段名、耗时和原始异常只放在诊断区域，不抢占主界面。

### 1.2 语气

- 操作界面：直接、清楚，不故作可爱。
- 策略说明：口语化，但必须具体。
- 吐槽伙伴：轻松、像坐在旁边看牌，不写成分析报告。
- 错误提示：先告诉用户该怎么恢复，再给技术原因。
- 不使用“猫猫”作为强行称呼；角色称呼由 N.E.K.O 当前角色决定。

### 1.3 长度

- 简洁悬浮窗：最多 3 行核心内容。
- 完整策略卡：每个方案只保留 1 个结论、1 个风险依据、1 个牌型影响和 1 个比较理由。
- 吐槽伙伴：通常 1–2 句。
- 主界面不逐张朗读完整手牌、完整牌河和四家全部分数。

## 2. 统一术语

| 统一名称 | 用途 | 不再使用或避免 |
| --- | --- | --- |
| 吐槽伙伴 | 控制猫娘是否观察牌局并主动搭话 | N.E.K.O 搭话、陪伴模式、吐槽模式混用 |
| 推荐打牌 | 控制是否显示具体弃牌建议 | 指导模式、策略模式开关 |
| 轻量判断 | 普通风险轻防、整体更积极 | 简易策略、轻量策略混用 |
| 完整攻守 | 完整比较风险、牌效和场况 | 完整策略、详细策略混用 |
| 简洁提示 | 外部窗只显示主结论和关键原因 | 简短版、简洁主建议混用 |
| 完整分析 | 外部窗展示三种方案和推理过程 | 详细、详情、完整卡片混用 |
| 传统识别 | 非 YOLO26 的旧识别链 | 原版、Legacy 直接展示 |
| YOLO26 识别 | 当前默认视觉识别链 | YOLO 模式、超级识别混用 |
| 悬浮窗 | 外部原生窗口 | 外部框、悬浮提示、外部面板混用 |
| 风险参考线 | 当前局面与画像允许承受的相对危险水平 | 风险预算、允许线在用户层混用 |
| 相对危险指数 | 0–100 的规则型危险刻度 | 风险概率、放铳概率 |
| 保形推进 | 在防守时尽量保留向听与有效牌 | 龟牌、半退 |
| 完全防守 | 风险过高时优先确保安全 | 全龟、全退作为主界面标题 |
| 本场 | 连庄累计场棒 | honba |
| 立直棒 | 桌面供托数量 | 仅写“供托”而不解释 |

`吐槽伙伴`、`推荐打牌` 和 `完整分析` 是三个独立维度，不能再用一个开关同时表达多个含义。

## 3. 外部悬浮窗：启动与设置页

```text

```

辅助说明：

```text
下面的选项都能在实战中修改
```

尚未开始捕获时，必须显示醒目状态条：

```text
当前尚未开始捕获
请选择下方一种打法；开始捕获后，吐槽伙伴才会观察牌局并搭话。
```

## 4. 外部悬浮窗：简洁提示

### 4.1 推荐打牌开启

固定结构：

```text
主建议：打{牌名}
原因：{最关键的安全或牌型理由}
最近牌型：{牌型}｜{向听}｜有效进张约{数量}张
```

示例：

```text
主建议：打北
原因：北已见2张，危险较低；切出后仍保留一向听和8张有效牌。
最近牌型：普通面子手｜1向听｜有效进张约8张
```

如果无法稳定给出具体牌：

```text
暂时不给具体牌
原因：手牌或牌河还没有稳定到足以排序候选。
最近牌型：{已确认结果或“等待稳定识别”}
```

不允许只显示“继续观察成型速度”而不解释为什么没有具体牌。

### 4.2 推荐打牌关闭

固定结构：

```text
局势观察：{当前最重要的变化}
攻守方向：{推进／保形推进／完全防守}，{一句原因}
最近牌型：{牌型}｜{向听}｜有效进张约{数量}张
```

示例：

```text
局势观察：下家已经立直，桌面压力上升。
攻守方向：先保形推进；手牌仍是一向听，不必立刻完全防守。
最近牌型：七对子｜1向听｜有效进张约6张
```

### 4.3 关键事件

| 场景 | 主文案 | 补充文案 |
| --- | --- | --- |
| 自摸按钮 | 自摸亮了 | 和牌事件优先于普通策略分析 |
| 荣和按钮 | 荣和亮了 | 和牌事件优先于普通策略分析 |
| 新立直压力 | {玩家}立直了 | 正在重新评估风险与牌型 |
| 鸣牌按钮 | 出现鸣牌选择 | 这里只记录界面事实，不自动替玩家操作 |
| 结算候选 | 正在确认本局是否结束 | 再检查一帧，避免误判 |
| 结算确认 | 本局已经结束 | 上一局已归档，等待下一手牌 |

## 5. 外部悬浮窗：完整分析

### 5.1 顶部结论

```text
{吐槽伙伴／风险分析}
{主建议：打某牌／当前局势观察}
{推进评估／保形评估／高压防守评估} · {最近牌型}
```

### 5.2 风险说明

固定格式：

```text
相对危险指数：{最低}–{最高}/100
当前风险参考线：{参考值}/100
```

必须紧跟说明：

```text
0–100 是规则型相对危险指数，不是放铳概率。
0–9 极低｜10–39 较低｜40–59 中等｜60–79 高｜80–100 很高
```

禁止只显示“风险 62”或“预算内”，因为用户无法知道方向和尺度。

### 5.3 三种方案卡片

方案 A：

```text
方案 A · 主建议
打{牌名}
危险度：{等级} {指数}/100，{低于／高于}参考线{差值}点
安全依据：{现物／筋／壁／字牌可见数等具体证据}
牌型影响：{向听变化}，有效牌{增加／减少}{数量}张
为什么：{选择该牌的核心原因}
```

方案 B/C：

```text
方案 {B/C} · 对照方案
打{牌名}
危险度：{等级} {指数}/100，{低于／高于}参考线{差值}点
安全依据：{具体证据}
牌型影响：{具体影响}
与 A 比较：{更安全／更保形／打点更高，但付出什么代价}
```

安全依据必须具体到牌。例如：

```text
中、发各已见2张，因此两张字牌的剩余碰出风险较低。
```

不能只写：

```text
字牌两张，风险较低。
```

### 5.4 完整分析分区标题

统一为：

1. `主建议`
2. `判断依据`
3. `场况影响`
4. `风险说明`
5. `方案 A/B/C`
6. `识别不确定性`

不再同时出现“为什么”“风险怎么算”“策略依据”“推理依据”等多套同义标题。

## 6. 吐槽伙伴文案

### 6.1 功能状态

| 状态 | 文案 |
| --- | --- |
| 已开启、尚未捕获 | 吐槽伙伴已开启，等待开始捕获 |
| 正在观察 | 吐槽伙伴正在观察牌局，遇到变化时会主动搭话 |
| 禁用 | 吐槽伙伴已禁用，牌局识别和策略分析仍会继续 |
| 等待会话 | 吐槽伙伴已开启，但当前没有可用的 N.E.K.O 对话会话 |
| 已生成事件 | 已生成一条牌局事件，正在交给 N.E.K.O |
| 已送达宿主 | 最新牌局事件已经送达 N.E.K.O，正在等待回复 |
| 消息链路不可用 | 已识别到牌局变化，但暂时没有送达 N.E.K.O；正在尝试恢复 |
| 回复失败 | 牌局识别正常，但 N.E.K.O 本次没有成功回复 |

“插件调用了消息接口”不能写成“已经送达”，更不能写成“猫娘已经说话”。只有宿主消息桥确认接收后才能显示“已送达宿主”；消息进入队列也不代表模型已经生成回复。

### 6.2 事件语气示例

起手牌稳定：

```text
这手看起来还有得长，先看看它往哪边靠。
```

普通推进：

```text
这几巡还挺安静，手里的形状倒是在慢慢顺起来。
```

单家立直：

```text
好家伙，下家立直了，桌上的气氛一下紧起来了。
```

多家立直：

```text
两家一起立直？这桌突然就不讲道理了。
```

自摸机会：

```text
自摸亮了——好嘛，这一下总算没白等。
```

结算：

```text
好，这局先到这儿，刚才那阵仗还挺有意思。
```

对玩家操作迟疑：

```text
哦对的对的……哎呀不对不对……对……对吗？
```

### 6.3 吐槽边界

- 不逐张念完整手牌。
- 不复述四家全部分数。
- 不告诉玩家应该打哪张牌。
- 不建议立直、吃、碰、杠或弃和。
- 可以表达赞同、迟疑、惊讶和分歧。
- 独特彩蛋必须低频，一次只能使用一个梗。
- 不在关键和牌或立直事件中强插彩蛋。
- 不提及梗的现实人物来源。

### 6.4 逆天模式

- 开关名：`逆天模式`。
- 辅助说明：`增加离谱但无害的彩蛋话术；一次只用一个梗。`
- 默认关闭。
- 只有吐槽伙伴开启时才能操作；吐槽伙伴关闭时显示 `需先开伙伴`。
- 开启后从独立话术卡池轮换一个主题，不逐字固定复读。
- 一条回复只能使用一张话术卡，不与铜须彩蛋、另一种口头禅或第二张卡叠加。
- 自摸、荣和、新立直和确认的新副露仍使用正常关键事件反应，不强插逆天话术。
- 仍须遵守吐槽边界：不编造事件、不播报内部数字、不提供打牌指导。

首批话术卡：

- `先别急，我先急一下。`
- `这合理吗？这不合理吧……嗯，合理吗？`
- `刚才还挺正常的，怎么突然有节目效果了。`
- `我大概看懂了。大概。`
- `这一下很有想法，具体是什么想法我再想想。`
- `哦对的对的……哎呀不对不对……对……对吗？`

## 7. 内部后台：顶部区域

### 7.1 标题与状态

建议标题：

```text
雀魂观察后台
```

```text

```

| 内部值 | 用户文案 |
| --- | --- |
| stopped | 已停止 |
| starting | 正在启动 |
| observing | 观察中 |

```text

```

```text

停止实战
按新局重置
刷新状态
```

如果已经有识别模式选择，不再额外放一个含义不清的“YOLO26 实战”重复启动按钮。

### 7.4 三个核心开关

```text
推荐打牌
```

## 12. 诊断与错误提示

### 12.1 窗口与捕获

| 情况 | 主提示 | 恢复提示 |
| --- | --- | --- |
| 未找到窗口 | 没找到雀魂窗口 | 请先打开雀魂，插件会继续自动重试 |
| 多窗口 | 找到多个雀魂窗口 | 请选择当前正在对局的窗口 |
| 窗口关闭 | 雀魂窗口已经关闭 | 窗口重新出现后会自动连接 |
| 截图失败 | 这次没有截到画面 | 正在自动重试，不会清空上一帧状态 |
| 画面遮挡 | 牌桌被菜单或其他窗口挡住了 | 已暂停更新并保留当前对局 |

### 12.2 识别

| 情况 | 文案 |
| --- | --- |
| 分辨率不匹配 | 当前画面还没有匹配到可靠的识别区域，请尽量使用16:9游戏画面 |
| 手牌不足 | 已识别{数量}张手牌，正在等待画面稳定 |
| 没找到手牌 | 暂时没有看到完整手牌，请保持牌桌无遮挡 |
| 牌河不稳定 | 牌河变化还不稳定，本帧不更新风险判断 |
| 点数不稳定 | 四家点数还没有稳定，本局暂不使用顺位策略 |

### 12.3 吐槽伙伴

| 情况 | 文案 |
| --- | --- |
| 功能禁用 | 吐槽伙伴已禁用 |
| 尚未开始捕获 | 吐槽伙伴已开启，等待你选择打法并开始捕获 |
| 捕获已经停止 | 当前没有观察牌局；重新开始捕获后才能继续搭话 |
